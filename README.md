# 🎬 摄影棚灯光方案与设备占用排期系统

摄影师在平面图上安排灯位、填写器材清单；场务核对灯具实物与各回路功率后确认时段。
确认时**同一事务内**锁定场地与灯具；拍摄结束逐件登记归还，损坏记录关联本次项目。

- **后端**：Rust + Axum + SQLx，SQLite 存储排期与方案版本（`backend/`）
- **前端**：Svelte 4 + Vite，SVG 可拖拽灯位平面图 + 甘特式占用时间线（`frontend/`）
- **本地模拟**：功率电表 `/api/power/live`、通知推送（落库 + 服务端日志）

## 一条命令启动

```bash
./run.sh
```

自动完成：安装/检测 Rust 与 npm 依赖 → 构建前端 → 编译后端 → 建库、写入演示数据 → 启动。
打开 http://localhost:8080 （前端与 API 同端口；可用 `PORT=8090 ./run.sh` 改端口）。

首次启动会创建 2 个摄影棚、5 条回路、11 盏灯（含 1 盏维修中）和 4 个演示账号：

| 身份 | 账号 | 说明 |
|---|---|---|
| 张伟（摄影师） | 用户 1 | 可建方案、提交、申请损坏豁免 |
| 李娜（摄影师） | 用户 2 | 第二摄影师，用于制造设备冲突 |
| 王磊（场务） | 用户 3 | 核对、确认排期、登记归还、审批豁免 |
| 系统管理员 | 用户 4 | 拥有场务全部权限 |

右上角下拉切换身份（本地模拟登录，请求头 `X-User-Id`）。
重置演示数据：停止服务后删除 `backend/data/studio.db` 再启动。

## 典型流程

1. **摄影师**：新建方案 → 在平面图上拖灯位 → 器材清单逐件选灯并指定回路 →
   右侧实时预检（设备冲突、每回路「既有占用 + 本方案」功率）→ 提交。
2. **场务**：打开项目核对实物与回路负载 → 确认。确认时再次计算互斥与功率，
   场地槽位与全部灯具占用在**同一数据库事务**写入。
3. **换灯 / 延时 / 换棚**：摄影师修改已确认方案 → 自动生成新版本、
   旧占用在事务内全部释放、状态回到「待确认」，必须由场务重新确认；版本与每次确认结论全程留痕。
4. **开拍 → 逐件归还**：每件灯单独登记「完好/损坏」；损坏自动建档并关联本项目。
   全部归还后才能完工，完工释放场地。
5. **取消项目**：任意时刻取消，灯具与场地占用立即释放，其他项目当场可排。
6. **损坏豁免**：摄影师可申请，但**不能审批自己项目的豁免**；须由场务/他人审批。

## 硬性业务规则（无法手工绕过）

每条规则都有**两道**防线：Axum 应用层先给出可读错误，SQLite 触发器是最终兜底——
即使直接操作数据库也无法写入违规数据：

| 规则 | 实现 |
|---|---|
| 同一灯具不能被两个项目同时段占用 | `trg_bookings_fixture_mutex`（重叠区间判定） |
| 同一场地不能被两个项目同时段占用 | `trg_slots_studio_mutex` |
| 回路重叠时段累计功率 > 上限，禁止放行 | `trg_bookings_no_overload`（按标称功率实时累计，**不存在强制确认参数**） |
| 维修/报废灯具不可占用 | `trg_bookings_fixture_usable` |
| 摄影师不能审批自己项目的损坏豁免 | `trg_damages_no_self_waiver` + 接口 403 |

边界语义：功率合计 **等于** 上限合法，超过即拒（`>` 判定）。

## 排期时间线

「排期时间线」页按行展示场地与每件灯具，色块表示各项目所占时段（占用中/已归还/已取消
三种颜色），红色竖线为当前时刻，点击色块直达项目。取消或归还后色块状态即时变化，
可直观看出资源已恢复。

## 模拟接口

- `GET /api/power/live?studio_id=1`：按当前 held 占用计算各回路负载，叠加 ±3W
  确定性抖动模拟现场电表读数（前端 3 秒轮询）。
- 通知：提交、确认、驳回、要求修改、取消、损坏上报、豁免申请/审批均生成站内通知；
  同时以 `[mock-notify → user N]` 输出到后端日志，模拟外部推送网关。

## 验证

```bash
# 服务运行中执行（36 项端到端断言）
PORT=8080 python3 scripts/e2e_check.py
```

覆盖：设备互斥、场地互斥、回路超限拒绝、边界等于上限、取消后立即复用、
换灯/延时重新确认与版本保留、逐件归还、损坏关联、自审批豁免拦截、权限边界、维修灯禁用。

## 主要 API

```
GET  /api/studios                     场地/回路/灯具目录
POST /api/validate                    干跑预检（不落库）
POST /api/projects                    摄影师建方案（生成 v1）
PUT  /api/projects/:id                修改方案（生成新版本；已确认则释放占用、待重新确认）
POST /api/projects/:id/submit         提交场务
POST /api/projects/:id/confirm        场务确认/驳回/要求修改（确认即锁定资源）
POST /api/projects/:id/start|complete 开拍 / 完工
POST /api/projects/:id/cancel         取消（立即释放全部资源）
POST /api/projects/:id/returns        逐件归还（可登记损坏）
POST /api/damages/:id/waiver/request  申请豁免
POST /api/damages/:id/waiver/decision 豁免审批（本人项目拒绝）
GET  /api/timeline?studio_id=1        场地+灯具占用时间线
GET  /api/power/live                  模拟电表
GET  /api/notifications               通知
```

## 开发模式

```bash
# 终端1：后端（跳过前端构建）
cd backend && DATABASE_URL="sqlite:data/studio.db?mode=rwc" cargo run
# 终端2：前端热更新（/api 代理到 8080）
cd frontend && npm run dev   # http://localhost:5173
```
